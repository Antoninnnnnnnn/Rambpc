Constructor/ART caveat — must not be hidden
------------------------------------------
Exactly THREE method implementations are replaced: aaqe.$init(),
aaqe.$init(byte[]), and aaqe.read(byte[],int,int). No other method is hooked.
Both constructor replacements NEVER invoke an original aaqe constructor (both
original overloads reach AudioRecord construction/start). They directly call only
java.io.InputStream.$init on the allocated object, then explicitly set a=false and
b=null and bind ONE armed recording. The unused byte[] constructor argument is
ignored, not treated as audio. The analyzed original close() tolerates b=null.

Direct superclass initialization on an already-allocated subclass through Frida
is an ART/JNI/bridge assumption, not validated by the host tests. Constructor hooks
can also be missed by pre-existing optimized/inlined callsites. No broad ART
optimization change is made. If this exact device/bridge cannot safely perform
this superclass-only initialization or does not emit the expected bypass event,
STOP: do not call original $init, do not hook generic AudioRecord, and do not widen
scope. The narrow alternative is an explicitly authorized test build/factory seam
that supplies a finite ByteArrayInputStream instead of constructing aaqe; that
would be a separate task, not an automatic recovery in this implementation.

The constructor-bypass event confirms only: this replacement ran, the original
constructor was not called by it, superclass initialization returned, b is null,
and the approved PCM was bound. It does NOT claim system-wide absence of audio
construction/start. The ready event deliberately includes
constructorBypassArtValidated=false.

Original aaqe.a() will return -1 because b=null; no real audio session exists.
Original aaqe.b() cancellation is respected by reads. Original close(), with b
null, does NOT set a; consequently it does not independently cancel the synthetic
source. Keep the app's normal reader shutdown, finite EOF and final RPC stop();
do not expect close() alone to interrupt a concurrent synthetic read. No close
hook was added because the approved scope is constructors + byte-array read only.

Exact RPC API — JSON-serializable values, no private-device file API
------------------------------------------------------------------
status() -> {phase,pin,deniedConstructors,bypassedConstructors,stream}
Initial phase is loaded, capture not permitted. No audio in this result.

prepare({
  constructorBypassApproved: true,
  ambientMicBlocked: true,
  approvedPcm: [ {sha256: LOWERCASE_HEX64, byteCount: EVEN_INTEGER}, ... ]
}) -> metadata with phase=ready, only after verification + all three hooks.
One-shot. There must be 1..3 explicit pre-approved descriptors. No capture is armed.
Acknowledgments mean MAIN has checked containment and accepts the documented ART
assumption. They neither change device state nor substitute for verification.

arm({
  sha256: LOWERCASE_HEX64,
  byteCount: EVEN_INTEGER,
  pcmBase64: CANONICAL_STANDARD_BASE64_WITH_PADDING
}) -> {armedCount,byteCount,sha256}
Descriptor must exactly match a prepare() approval. Decoded bytes are rehashed.
Only headerless PCM16LE, mono, 16000Hz is authorized. Positive even byteCount must
be <=640000 (20s * 16000 samples/s * 2 bytes). No WAV/Ogg/FLAC/ID3 containers,
URL, shell command, filename or transport service is accepted. The source format
itself cannot be proven from headerless bytes: MAIN must generate/approve it.
Base64 has exact declared size and canonical padding. Invalid payload/hash does
not consume an arm. Do not log or echo arm input. Approval does not authorize more
than the <=3 already-authorized controlled phrases; no personal speech/data.

For each controlled phrase MAIN can read a pre-approved PRIVATE HOST file into
memory, not log it, verify its expected hash and size, then call api.arm:
    import base64, hashlib
    with open(APPROVED_PRIVATE_HOST_PCM_PATH, 'rb') as f:
        pcm = f.read(640001)
    assert 0 < len(pcm) <= 640000 and len(pcm) % 2 == 0
    assert len(pcm) == EXPECTED_BYTES
    assert hashlib.sha256(pcm).hexdigest() == EXPECTED_SHA256
    api.arm({'sha256': EXPECTED_SHA256, 'byteCount': EXPECTED_BYTES,
             'pcmBase64': base64.b64encode(pcm).decode('ascii')})
    del pcm
Approval hashes/size must be fixed before prepare. No PCM or payload file needs to
be written into this scratch directory, the repository, logs or any artifact store.

Each successful arm consumes one of THREE lifetime arm slots, including an arm
later stopped/cancelled. Exactly one pending arm, one recording at a time. The next
aaqe constructor consumes that arm and resets the new recording's position/clock.
An unarmed/additional constructor throws fixed IOException without calling either
original constructor; read on unknown/pre-existing objects also fails closed.
No cap-reset API, retries, silence padding, looping, replay fallback or auto-arm.
Do not reload/recreate an agent to evade its lifetime cap.

After the UI triggers ONE capture, require a constructor-bypass event with the
matching source hash/count. Then require eof with deliveredBytes=byteCount and
deliveredSha256=sha256 before arming the next phrase. Do not count an interrupted
or cancelled recording as a successful EOF. All arm attempts across this lab run
must stay within three, regardless of any host-side restart.

stop() -> metadata phase=stopped; irreversible. Cancels pending/in-flight/future
reads and refuses all future constructors/arms. It deliberately DOES NOT remove
hooks. A cancelled in-flight read returns -1 without committing byte count. A copy
already in progress may have touched the caller buffer before stop wins; the caller
must ignore it when the return is -1. Read validation errors still throw; a valid
zero-length read on a known recording returns 0 even at EOF/stopped.
No forced detach/unload/session kill, shell or service operation is exposed.

Read semantics and observation limits
------------------------------------
read([B,offset,length) validates null/bounds without integer-overflow arithmetic.
Nonnegative positive reads deliver min(requested,remaining,640) bytes exactly;
odd byte boundaries are supported by the stream contract. There is no silence
padding and EOF returns -1, repeatedly. A zero request returns 0 without consuming.
Pacing uses android.os.SystemClock.elapsedRealtime and at most 20ms sleep pieces;
the deadline is firstReadTime + cumulativeDeliveredBytes/32 milliseconds. Delayed
readers can catch up but cannot deliver ahead of that cumulative real-time bound.
The entire approved stream is finite; the delivery duration is <=20s of PCM, not
a guarantee that a stalled application finishes within 20s of wall time.

The JS runtime serializes pure state transactions. A busy lease spans Java calls
and sleep; concurrent/reentrant reads are denied with IOException rather than
blocking on a Java lock and risking a Frida JS-lock/Java-lock deadlock. At most one
read per object succeeds at a time; byte positions never duplicate or reset within
that recording. Abort/cancellation stops only that finite recording; MAIN should
stop the overall test on an unexpected read exception, not retry it.

Observations: loaded/ready/armed/constructor-denied/constructor-bypass/eof/stopped/
fatal events; SHA256, byte counts, IDs and state flags only. EOF additionally hashes
actual bytes copied through successful reads using a per-recording MessageDigest.
No audio bytes/base64, transcript, credentials, device file paths or phrase labels
are sent by these events/status. Host must likewise avoid printing RPC arguments.
No auth, TLS, attestation, feature, safety, response, encoder or generic AudioRecord
handlers are hooked or changed. The original app's downstream behavior is not
reimplemented or bypassed by this script.
