# Sambler engine roadmap

**Goal.** Deliver a Rust SDK that takes an audio stream and editing context, then returns reliable text or an actionable error on Windows, macOS, Linux, Android and iOS. The future app will provide the microphone, active document and interface. Current checks and the starting test are in the [getting started guide](../app/README.md).

Plan established on 18 November 2026 at revision `9a29ab8`. The available Xiaomi completed 40 local sessions with the same texts as Windows. Two problems were reproducible without a recognition service: Android transport could not find default roots, and the 30 s overall limit interrupted a 31 s WAV at real-time cadence. [Historical audit](research/audit-moteur-20261118.md) · [Measurements and versions](evidence/audit-moteur-20261118.json)

Since the audit, `7ceb590` passed the [10 Rust jobs](https://github.com/Antoninnnnnnnn/Sambler/actions/runs/44373609858) and [4 Python jobs](https://github.com/Antoninnnnnnnn/Sambler/actions/runs/44373609771) before going to `main`. The collector segments audio over successive independent RPCs; [609.03 s on localhost](evidence/rust-long-pcm-loopback-windows-20261118.md) are covered in four segments without loss or duplication, retaining only completed segments on an injected error. This test is accelerated, with predetermined responses. It qualifies neither real-time cadence over five minutes nor remote recognition.

[Completion diagnostics and endurance](evidence/rust-native-real-reliability-20261118.json) separate what the client observes from delivery to the peer. A historical `DeadlineExceeded` and two stops around 300 s are documented; their causes are not established. No local success demonstrates authorized service access for a distributed application.

The corrective batch (`7d9af7b` for the validated code) passes on Windows with Rust stable and 1.88: **526 tests passed, 2 ignored**, plus **24 CLI tests without audio** per toolchain; formatting and strict Clippy pass. The integrated Python suite passed **931 tests, 4 skipped** in three instrumented runs. TLS in the canary APK and local dictation at real-time cadence are detailed below. Cross-platform CI for this new batch remains separate from that of `7ceb590`.

The [second audit](research/audit-parite-integration-20261118.md) identified four integration points: capture must not wait for the previous segment to finish; validated segments must remain recoverable after cancellation; text must not be joined with a mandatory space; rich editing must preserve the correct occurrence of repeated text. The APIs and [Windows validation on Rust stable and 1.88](evidence/rust-capture-fidelity-windows-20261118.md) of these fixes are documented. The audit's endurance measurements are local: 1,001 sessions per platform (901 expected successes and 100 injected failures), not a WAN or battery-life measurement.

The independent audit of commit `9120dec` then reproduced a misleading success when a compatible segment contained no usable text and noted that the editor example still used a general diff for a selection. The [next batch](evidence/rust-integration-outcomes-windows-20261119.md) distinguishes no result, text, review, supported deletion and refusal; the long summary preserves previous segments without announcing overall success when a segment is missing. The example checks editor identity and targets a selection only if its scope is proven. Telemetry mode excludes CLI content, and the Python reference limits cleartext transport to loopback. These checks do not measure dictation on the real service.

## 1. Make the Android connection work with phone settings

- The [Android transport](../crates/rambler-transport/ANDROID_TLS.md) initializes the app's trust policy through public Android APIs. It retains the original name for that policy, certificate DNS/IP verification and `h2` ALPN. The SDK distinguishes unavailable trust, certificate rejection, resolution failure and timeout; existing CLI categories remain stable.
- **Verified on Xiaomi/API 34.** The ordinary APK received an h2 PONG from a public server and a local server with an app-scoped CA. The same local peer with the wrong name was rejected. Authorized installation used root; the test process was non-root and was uninstalled. [Results and limits](evidence/android-tls-host-app-20261118.md)
- **Also verified on API 36/16 KiB.** The x86_64 APK loaded in the official emulator with 16,384-byte pages. It received an h2 PONG with the app-scoped CA and rejected the same peer with the wrong name. [Results and limits](evidence/android-tls-host-app-20261118.md)
- **Also verified by the second audit: more restrictive app policy.** On API 36 x86_64 with ARM64 translation and 4 KiB pages, both the SDK and Java client rejected the certificate when the domain policy accepted only the test authority. This check is separate from the x86_64 16 KiB trial. [Second audit measurements](evidence/audit-parite-integration-20261118.json)
- **Remaining.** Exercise a server requiring SCTs supplied only by TLS and the ARM64 + 16 KiB page combination. Xiaomi covers ARM64 at 4 KiB; the test loaded at 16 KiB covers x86_64.

## 2. Give long dictation a usable duration contract

- The [opt-in profile](research/interactive-pcm-dictation.md) segments at 120 s by default. It reserves a separate timeout for finalization after EOF and cleanup, without changing explicit timeouts or the classic CLI.
- [Local validation at real-time cadence](evidence/rust-interactive-wall-cadence-windows-20261118.md) covers 31 s and 300 s: sample ranges match durations derived from Ogg granules. A peer withholding its response produces `finalize_timeout`. The accelerated matrix covers 29, 30, 31, 120 and 300 s with a terminal audio marker.
- [Joining shared by the SDK and CLI](research/sdk-integration-guide.md#opt-in-to-long-dictation) retains individual texts, already supplied spaces and paragraph breaks. It does not insert a space in `L’équipe` or `明天开会。`. This display rule does not reconstruct cut words or recognized context between two RPCs.
- **Remaining.** Verify the final words and perceived delay on natural voices under capture conditions and with authorized service access. The local peer does not transcribe audio. [Options and session completion](../crates/rambler-engine/src/engine.rs)

## 3. Survive disconnections and release resources

- **Verified locally.** A controlled TCP cut during audio, while waiting for context or after half-close before gRPC status validates no text from that call. The old engine does not consume the next source or reconnect. A new explicitly opened engine handles an isolated new dictation. [TCP regression](../crates/rambler-engine/tests/app_tcp_recovery.rs)
- The [delivery API](research/recoverable-segment-delivery.md) transfers each result and its sample range after verified RPC completion. A normal stop processes the end of capture; abandonment or failure does not revoke already delivered results. Ctrl-C retains these segments in private JSON output, without validating the active call or producing global text. A separate manual attempt requires bounded opt-in, normal EOF and successful cleanup.
- Then exercise Wi-Fi disconnect and restoration, wake from sleep and a new dictation on the app target. Use explicit reconnection for the **next** session.
- Distinguish network loss, service refusal and temporary rate limiting. Pass a retry delay to the host when the service supplies one. Verify that a series of failures starts no background connection loop.
- Test a fast producer, slow consumer, two concurrent sessions and engine closure during capture. Record bytes, samples, tasks, handles and memory during a series of sessions in one process. Verify queue bounds and resources returning to their resting level after warmup.
- Keep the two historical incidents separate. For the incomplete native session at 282 s: record the last sample, end of sending, S3 end and gRPC status during a new authorized observation. On Python, two distinct cancellation defects were reproduced and fixed, and 200 bounded repetitions of the audited scenario completed. The cause of the historical wait was not established. [Python validation](evidence/python-transport-cancelled-close-windows-20261118.md)
- **Verification.** Success requires complete source transmission, its closure, S3 end and gRPC OK status. In the disconnection matrix, zero partial text presented as final, zero audio automatically resent and zero results attributed to the next dictation. The new session works after network restoration. The endurance report includes failures and resources still open. [Connection lifecycle](research/rust-connection-lifecycle.md) · [Native incident](evidence/rust-incomplete-diagnostic-followup.json) · [Python test](../tests/test_transport.py)

## 4. Measure and improve quality on real voices

- Start with a proposed batch of **40 spontaneous utterances**, mostly French, supplemented by English and bilingual sentences. Vary speakers, accents, speed, noise and pauses. Include negations, dates, times, proper names, hesitations, self-corrections and intended repetitions. The natural corpus already run through the Rust engine represents 18.885 seconds. [Existing corpus](evidence/rust-native-natural-public.json)
- The [FR/EN annotation plan](research/quality-annotation-plan.md) sets criteria before recording: acceptable text, information to preserve, expected action, noise and bilingual scenes. Invented examples are not recognition results. Reserve sentences and speakers for later validation.
- Include two cases where the same cleanup operation would have opposite effects. In « mardi à quinze heures… non, jeudi à quinze heures », the expected day is Thursday. In « c’est très, très important », both instances of « très » are part of the intended message.
- Measure word error rate for literal dictation, punctuation, errors on numbers and negations, lost repetitions and edit success. Test the same utterance with and without contextual vocabulary or secondary language when that setting is under consideration.
- **Verification.** Publish case counts, successes, errors and an explanatory example for each category. Retest « Merci de envoyer » in particular, a language change mid-sentence, and a sequence with an intentional repetition. Compare Rust rendering to PixelBoard 1.3.5 on the Xiaomi with matched initial text, selection and utterance. Record any difference in audio capture. [Real campaign](evidence/rust-native-real-campaign-20261118.json) · [PixelBoard observations](evidence/pixelboard-vs-native-real-20261118.json)

## 5. Apply an edit to exactly the right scope

- Verify replacement of a single word, rephrasing a selection, shortening, tone change, adding emoji and correction after a first dictation. Place control text on both sides. Also test insertion, deletion, an empty proposal and a result containing the entire history.
- Exercise existing `Strict`, `AsrOnly` and `S3ClientCompatible` policies. Cover multiple hypotheses, multiple finals, a replaced preview, unknown safety status and an ambiguous result. An instruction transcribed literally must retain that provenance. Send and clear commands require an explicit host decision.
- The [edit verifier](research/edit-acceptance-contract.md) now separates compatible proposals, on opt-in, from strict results. Offline tests cover the complete window, UTF-16 selection, graphemes, duplicate finals, unknown safety and document/revision/anchor conflicts. Matched speech validation remains to be done.
- `derive_selection_splice` is an option separate from the general text diff. With a still-exact window and revision and a structured response proving the anchor, deletion of the first `oui ` in `oui oui` preserves the link on the second. Without that proof, the SDK rejects the targeted proposal instead of guessing the range. [SDK guide](research/sdk-integration-guide.md) · [Styles test](../crates/rambler-engine/tests/splice.rs)
- **Verification.** All deterministic cases preserve control text. Stale context yields a conflict and leaves the document intact. For real cases, report understood intent, text correctness and proposal scope separately. [Edit contract](research/edit-acceptance-contract.md) · [SDK API](research/sdk-integration-guide.md) · [Grapheme tests](../crates/rambler-engine/tests/splice.rs)

## 6. Measure the delay experienced by the person dictating

- The host can timestamp its last sample on the monotonic clock and compare it with [`SessionDiagnostics::validated_eof_at`](research/interactive-pcm-dictation.md#independent-sdk-timing-seam) for a session it owns. Diagnostics distinguish sending and verified completion; the first protocol event is not necessarily text. Separately timestamp connection ready, first usable preview and app rendering.
- Measure **last sample → validated final result** on cold then reused connections, on desktop and phone. Compare controlled local network, Wi-Fi and mobile network. Give sample size, dispersed values and failures with the median and, where the series permits, the 95th percentile.
- Profile CPU, memory, startup, transmitted volume and heat during successive sessions. For battery life, repeat a scenario of the same duration under comparable screen, charge and network conditions. Encoding five seconds of PCM at 16 kHz already took 22 to 48 ms on the Xiaomi. Approximate historical end-of-dictation medians reached 373 ms in French and 388 ms in English on Windows.
- **Verification.** For each dominant cost identified, compare one change at a time on the same audio. First candidates are connection reuse, Ogg page duration and copies on the audio path. Retain a change when the gain over the complete session is reproducible and quality, consumption and end delay remain acceptable. [Xiaomi measurements](evidence/audit-moteur-20261118.json) · [Windows CPU profile](evidence/rust-native-pcm48-session-cpu-windows-20261118.md) · [Measurement method](performance.md)

## 7. Make audio input predictable on target platforms

- The [optional capture buffer](research/rust-pcm-capture.md) accepts PCM blocks from a callback without waiting for the reader. It reserves memory in advance; exceeding capacity is an explicit failure. Tests artificially withhold a final while blocks representing 60, 600 or 900 ms are offered; they verify packets, granules and overflow, as well as continuous 48 → 16 kHz conversion. These are not hardware callback delay measurements.
- Consolidate existing paths for mono PCM16 at 16 and 48 kHz and continuous Ogg/Opus. Vary block size, incomplete last block, absence of speech and queue pressure. Verify decoded duration, sample order and audible ending with an independent decoder.
- Inventory formats supplied by future hosts. If a common format is missing, prioritize its adapter, for example 44.1 kHz, floating-point or stereo. Then test clipping, mono conversion, filtering and fidelity on natural voices. If recordings reveal a noise or end-of-speech problem, evaluate targeted processing of final consonants and pauses.
- **Verification.** The same signal split differently retains its content and duration. The app receives a precise diagnostic for an incompatible format or abandoned capture. Packet-size differences across architectures are judged by decoding and effect on the result. [Audio pipeline](../crates/rambler-audio/BUILDING.md) · [Qualification kit](research/native-qualification-kit.md)

## 8. Deliver a usable SDK and detect regressions

- Use the [automated checks](../app/README.md#what-github-checks) as a starting point. On Android, load the library in the APK and cover 4 and 16 KiB memory pages. On iOS, supplement simulator tests with an in-app test on an iPhone. Compare dictation and replacement with the same audio file on each available platform and state the last verified step.
- Stabilize the public flow “open → supply audio → stop or cancel → read result → close”. Verify reuse after error, specify who releases each resource and preserve CLI output compatibility. If the app language requires a native bridge, expose this flow and test audio buffer and callback lifetimes from that language.
- Run short end-to-end scenarios and Rust/Python comparison on known responses in CI. Retain redacted fixtures for newly observed formats, including unknown fields, multiple results and late finals. Diagnose service changes by version and provenance.
- Produce duration, volume, stage and error-category diagnostics by default. Test with fictional markers that dictated text, selection, audio and private metadata remain out of logs and incident reports. Recheck dependencies and the Opus library at each update.
- **Verification.** Each target delivers a loadable artifact and completes dictation, editing, cancellation and a new session after disconnection on a local server. A CI failure identifies the precise target and stage. [Integration example](../crates/rambler-cli/examples/minimal_app.rs) · [CI matrix](../.github/workflows/rust.yml) · [Robustness coverage](research/native-robustness-coverage.md)

## Features to explore after the foundation

- **Composition, draft continuation and history.** Define cases with instruction and expected effect for `COMPOSE`, `RAMBLE` and `RAMBLE_HISTORY`. In published composition and continuation trials, the service returned the instruction literally. Expose a capability only when an observed response and its effect on text distinguish it from ordinary dictation. Until then, make its “unconfirmed” status available to the host. [Fidelity matrix](research/rust-feature-parity.md) · [Composition trials](research/composition.md)
- **Network unavailable.** Report the interruption and allow a fresh dictation when access returns. The Windows product uses Rambler/Jetson exclusively. On a loss of access it stops capture, offers any completed text for manual recovery and keeps the optional history accessible. [Windows product decisions](windows/README.md) · [Outages and recovery](windows/06-confidentialite-et-continuite.md)
- **Other languages and architectures.** Extend the matrix according to target users. Each addition repeats the same adapted corpus, language-specific writing tests and a run on the announced target.

**To integrate the app**, start from the [getting started flow](../app/README.md) and test capture through the stated duration, recovery after disconnection and edits that preserve the rest of the document. Measure French and English quality and delay between capture completion and final text.

## Cadence

One owner per active theme, a clean worktree and build cache. The owner implements, builds, fixes and validates their batch through to a usable deliverable. The coordinator settles interfaces and dependencies, integrates batches that pass together and monitors CI in the background.

Communicate when a result, decision or blocker changes the plan, not after each build. Do not keep an agent busy if its next step changes no decision. A worktree isolates code, not secrets: delegated work remains free of private data and provider calls.
