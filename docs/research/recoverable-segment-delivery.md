# Recovering completed segments from long PCM dictation

Use `rambler_audio::stream_long_pcm_dictation` when a host wants to take ownership of each segment instead of keeping an ever-growing `LongDictationResult`. The collector calls a synchronous sink with a `CompletedDictationSegment`: its zero-based index, its absolute half-open sample range in the 16 kHz PCM input, and its owned `DictationResult`. Ranges count real input samples, not Opus padding. With upstream resampling they refer to the resampler's output.

Delivery is in capture order, after clean upload and engine EOF, S3 END, gRPC OK and per-RPC cleanup; it happens before the next RPC starts. Final-looking responses, S3 END alone and a failed RPC do not trigger delivery. The collector neither holds delivered results nor copies the entire PCM source. The limits still apply to each RPC. `stream_long_pcm_dictation_with_observer` combines the same sink with the existing preview events; `SegmentCompleted` follows delivery. The legacy accumulating API and its error's `completed` field are unchanged.

The sink runs on the collection task. Keep it short and nonblocking, and do not log its contents. If handing results to another task or storage, the host owns queue bounds, full-queue handling, persistence failures and retention policy. Delivery confirms protocol completion, not text safety or authorization to apply edits. A segment can contain private or safety-blocked structured data, or be ambiguous; use the engine's safety-checked projection before displaying text and treat any explicitly persisted result as private.

For a mixed capture, keep each delivered range with its `segment.result.interpret(policy)` outcome and preserve capture order. `UsableText` supplies the safe projection for that range; `NoResult` and `NeedsReview` mark gaps, not acoustic silence. A `VerifiedDeletion` is a scoped edit result, not usable dictation text or permission to delete across ranges. Keep safety outcomes separate from ordinary gaps and do not surface their raw candidates. Report a mixed/partial projection only after clean collection completion and in the absence of safety failures; a later error or abort remains an error or abort. This needs no second collector or join: display the stored ranges and do not emit or apply text from an already-consumed range a second time at EOF. See the [interactive CLI contract](interactive-pcm-dictation.md#cli) for the JSON representation.

| Host action | What happens |
| --- | --- |
| Stop and keep the capture | Stop admitting new samples, enqueue the remaining capture and call `CaptureSender::finish()` or `PcmSender::finish()` (or return clean EOF from a custom source). Keep polling. The collector drains accepted PCM and finalizes the last nonempty segment. Only `Ok(())` confirms clean completion of the whole source. |
| Abort | Drop the collection future. The active RPC is cancelled, with best-effort upstream closure on the live Tokio runtime. No later segment is delivered and already transferred results remain with the sink. Use `Engine::close` to await engine cleanup at shutdown; capture source closure on drop is scheduled separately. |
| Later source, RPC or cleanup failure | The collector closes the source and reports the error without retrying or replaying audio. It does not deliver the failed segment or claim successful completion; earlier deliveries remain valid. |

`rambler dictate-wav INPUT.wav --interactive` treats Ctrl-C as **abort**, not as clean file EOF. It prints one private stdout JSON object with `type: "error"`, `category: "cancelled"` and only the previous completed segments, in order, with their exact `[start, end]` `sample_range`. There is no top-level joined `text`; exit status is 130. The CLI cancels before projecting the retained segments and continues to withhold safety-blocked text. Normal file EOF drains and finalizes; a later failure remains an error even when it includes earlier results. The CLI retains segments for this single output; for long-running capture with bounded retention, use the SDK sink and bound what your app keeps.

Local regression tests hold the second RPC open after its final response and S3 END. They verify ordered ownership transfer, release of consumed PCM backing storage, normal stop draining a queued five-sample tail, cancellation without waiting for trailers, and a late gRPC failure without replay. The CLI supervisor regression injects the same signal result as Ctrl-C while a loopback peer holds a later RPC. It verifies that a committed gap does not change cancellation precedence and that blocked and uncommitted text stay out of stdout. These are synthetic loopback checks, not microphone or remote service measurements.
